Speech Search Flow
1

User taps mic button

Button turns red with animated waveform bars. Mic icon pulsates. Status message: "Listening… speak in Tamil, Hindi or English". Recognition starts simultaneously on ta-IN, hi-IN, en-IN (three parallel SpeechRecognition instances).

const recognizers = ['ta-IN','hi-IN','en-IN'].map(lang => {
  const r = new SpeechRecognition();
  r.lang = lang; r.interimResults = true;
  return r;
});
2

Confidence-based language winner

Each recognizer fires onresult with a confidence score. The recognizer with the highest confidence for its final result "wins" and provides the transcript. For code-mixed speech, merge transcripts from all three.

// Winner = highest confidence final result
const best = results.reduce((a,b) =>
  b.confidence > a.confidence ? b : a);
3

Language validation check

If none of the three recognizers produce a confident result (all below threshold ~0.4), classify as "unsupported language". Show toast: "Please speak in Tamil, Hindi, or English". Stop all recognizers and reset to idle.

4

Keyword extraction & normalization

Extract product-relevant terms from the transcript. Map Tamil/Hindi synonyms to English product names using a local keyword dictionary (e.g., "அனார்" → "flower pot", "फुलझड़ी" → "sparkler"). Handle typos with fuzzy matching.

const SYNONYMS = {
  "அனார்":"flower pot","فولجهड़ी":"sparkler",
  "पटाखे":"cracker","ராக்கெட்":"rocket"
};
5

Product list filtering

Run normalized keywords against product names, product codes, and category names. Rank results: exact match → starts-with → contains. Scroll the product table to the first match, highlight matching rows, and update the category filter dropdown if a category name was spoken.

6

Results + feedback

Show matched transcript in the search box (e.g., "You said: sparkler"). Display match count badge ("22 products found"). Mic resets to idle. If no match found: "No products found for 'term'. Try: sparkler, rocket, bomb…"

State Machine
idle
Mic button visible and ready. Search box shows placeholder text. No recognizers active.
→ listening on tap
listening
Mic is red. Waveform animates. All 3 recognizers active. Interim transcript shown in search box as user speaks.
→ processing on silence/final
processing
Recognizers stopped. Confidence winner selected. Keyword extraction running. Spinner shown.
→ results or error
results
Products filtered and scrolled to. "You said: …" shown. Match count badge visible. Mic ready for next query.
→ idle on clear
unsupported
Toast: "Please speak in Tamil, Hindi, or English." Mic resets. No product changes made.
→ idle on dismiss or retry
no-speech
No audio detected for 5 seconds. Mic auto-stops. Soft message: "No speech detected. Tap to try again."
→ idle after 3s

Key Technical Considerations
Browser support

Web Speech API supported in Chrome 25+, Edge 79+, Safari 14.1+. Firefox requires fallback (no native support). Show "use Chrome/Edge for voice search" for unsupported browsers.

Mic permissions

Prompt getUserMedia on first tap. Cache permission state. On denial, show: "Enable microphone in browser settings to use voice search."

Performance

Three parallel recognizer instances are lightweight. Stop all on first final result to free resources. Debounce interim results to avoid excessive re-renders.

Accessibility

Mic button with aria-label="Start voice search". Live region for recognition status. Keyboard shortcut (Alt+M) to toggle. Never remove text search fallback.

Offline graceful

Web Speech API requires internet. On network loss, show "Voice search needs internet connection" and revert to text search silently.

Mobile-first

Auraa's audience is primarily mobile. Mic button must be thumb-reachable (min 44×44px). Listening state UI must be clearly visible at small viewport sizes.
